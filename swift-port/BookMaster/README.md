# BookMaster.xcodeproj

The whole app, in one Xcode project — no separate Swift package to
reference, no shell scripts, no `swift run`. Open `BookMaster.xcodeproj`
in Xcode and hit Run.

## Structure

Everything lives directly under this directory as regular members of
one of two targets:

- **`BookMaster/`** — the app target. Everything: UI (`BookMasterApp.swift`,
  `Views/`), models (`Models/`), state stores (`Stores/`), and all
  business logic (`Services/` — USB detection, disk image authoring,
  the raw-write safety gate, ffmpeg encoding, the Create/Check Master
  pipeline, ...), plus bundled resources (`Resources/config.json`,
  `Resources/books.csv`) and `Info.plist`.
- **`BookMasterTests/`** — the `BookMasterTests` unit test target (31
  tests), hosted inside the app process (`TEST_HOST`/`BUNDLE_LOADER`,
  matching Xcode's own "Unit Testing Bundle" template) so
  `@testable import BookMaster` can see the app target's internal
  declarations.
- **`BookMaster.xcodeproj`** — generated by
  [xcodegen](https://github.com/yonaskolb/XcodeGen) from `project.yml`,
  not hand-edited. After changing `project.yml`, run `xcodegen generate`
  again (`brew install xcodegen` if you don't have it) rather than
  editing the `.xcodeproj` directly.
- **`project.yml`** — the actual source of truth for target settings:
  bundle identifier (`co.uk.voxblock.bookmaster`), deployment target
  (macOS 13), and `Info.plist` properties including
  `NSCameraUsageDescription`, the key
  [HISTORY.md](HISTORY.md)'s Phase 5/9 sections found is a hard
  requirement before camera access works at all.
- **`HISTORY.md`** — the full phase-by-phase build log (Phases 0-9):
  what was built, how each piece was tested, and every real finding
  along the way (the removable-but-not-USB gotcha, the `hdiutil` bug
  and its fix, the camera TCC requirements, ...). Worth reading before
  changing anything in `Services/` — the reasoning behind non-obvious
  choices lives there, not as comments scattered through the code.

There used to be a separate `BookMasterCore` Swift package the project
depended on; it's gone now, folded entirely into `BookMaster/` as
regular target sources, because a single unified project is simpler to
navigate than a package-plus-thin-app-target split. `HISTORY.md` still
talks about that intermediate structure in places — it's accurate for
when it was written, not for right now.

## Verified

- `xcodebuild -project BookMaster.xcodeproj -scheme BookMaster build`
  succeeds cleanly.
- `xcodebuild -project BookMaster.xcodeproj -scheme BookMaster test`
  succeeds: **31/31 tests pass**, now running hosted inside the actual
  app binary (a more realistic configuration than the old package's
  standalone `swift test`, which tested the same logic compiled as a
  separate library rather than as part of the shipping binary).
- Inspected the built `.app` directly: `Info.plist` has
  `NSCameraUsageDescription` and the correct `CFBundleIdentifier`;
  `config.json`/`books.csv` land straight in `Contents/Resources/` —
  no nested resource bundle needed anymore (that was purely an
  SwiftPM artifact from the old package structure).
- Launched via `open`, runs without crashing.

## Not verified from this session

- Interactive use: clicking through the UI, granting the camera
  permission prompt, scanning a real barcode, plugging in a USB drive,
  writing to one. All of Phase 0/2/4's "needs a human with real
  hardware" caveats still apply.
- Running/debugging from within Xcode itself (Cmd-R) — only checked via
  command-line `xcodebuild` so far.

## Not done here, and why

See `HISTORY.md`'s Phase 9 section for the full list (Developer ID
signing, notarization, bundling+signing `ffmpeg`, hardened runtime
entitlements, a privileged write helper, an app icon, Sparkle updates,
settings/config migration from the Python app). Nothing about this
restructuring changes that list or brings any of it closer to done —
it is purely an organizational change to how the same code is packaged
for Xcode. **Nothing here touches, disables, or replaces the Python
app.** Cutover remains a decision for whoever owns this product.
