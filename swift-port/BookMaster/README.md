# BookMaster.xcodeproj

The real, native Xcode app project. Open `BookMaster.xcodeproj` in
Xcode and hit Run — no `swift run`, no shell scripts.

## Structure

- **`BookMaster/`** — the app target's own sources: `BookMasterApp.swift`
  (the `@main` entry point) and `Views/` (`ContentView.swift`,
  `CameraPreviewView.swift`). Nothing else lives here; all non-UI logic
  is in the `BookMasterCore` package.
- **`BookMaster.xcodeproj`** — generated by [xcodegen](https://github.com/yonaskolb/XcodeGen)
  from `project.yml`, not hand-edited. If you change `project.yml`, run
  `xcodegen generate` again rather than editing the `.xcodeproj`
  directly (installed via `brew install xcodegen` if you don't have it).
- **`project.yml`** — the actual source of truth for the project's
  settings: bundle identifier (`co.uk.voxblock.bookmaster`), deployment
  target (macOS 13), and `Info.plist` properties — including
  `NSCameraUsageDescription`, the exact key
  [Phase 5/9](../BookMasterApp/README.md) found is a hard requirement
  before camera access works at all.
- **`../BookMasterApp/`** — the `BookMasterCore` Swift package this
  project depends on (referenced as a local path package in
  `project.yml`). All the actual logic — settings, USB detection, disk
  image authoring, the raw-write safety gate, encoding, the Create/Check
  Master pipeline — and all 31 tests live there. See that directory's
  README for the full phase-by-phase build history.

## Why a separate Xcode project instead of just `swift run`

Phases 0-9 were built and tested entirely via SwiftPM (`swift build`/
`swift run`/`swift test`) — fast to iterate on, and sufficient for
everything except one thing: **TCC-gated capabilities (camera access)
need a real `.app` bundle with a proper `Info.plist`, launched through
LaunchServices, not a bare executable.** Phase 9 proved this by hand-
assembling a bundle with a shell script; this project supersedes that
script with the real thing — proper `Info.plist` management, an asset
catalog for a future app icon, and the Signing & Capabilities UI needed
once real Developer ID signing happens (see Phase 9's "Not done here,
and why" for what that still requires).

## Verified

- `xcodebuild -project BookMaster.xcodeproj -scheme BookMaster build`
  succeeds cleanly.
- The built `.app` has `NSCameraUsageDescription` and
  `CFBundleIdentifier` correctly present in its `Info.plist`, and
  `BookMasterCore`'s bundled resources (`config.json`, `books.csv`)
  land in `Contents/Resources/` automatically via Xcode's own Swift
  Package integration — no manual resource-copying step needed, unlike
  the retired shell-script packaging.
- Launched via `open` (required — see Phase 9), the built app runs
  without crashing.

## Not verified from this session

- Interactive use: clicking through the UI, granting the camera
  permission prompt, scanning a real barcode, plugging in a USB drive,
  writing to one. All of Phase 0/2/4's "needs a human with real
  hardware" caveats still apply — this project makes the app easier to
  launch and iterate on, it doesn't change what needs physical testing.
- Running the app *from within Xcode itself* (Cmd-R) — only validated
  via `xcodebuild` from the command line so far.
